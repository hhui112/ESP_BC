# 盛和养老固件 V2.3.4 更新说明

**基准版本：** V2.2.4（`BC_ESP_2026_2_2_4`）  
**本版版本号：** `BC_ESP_2026_2_3_4`

---

## 一、涂鸦 IoT / MQTT 迁移

1. **Broker 迁移**
   - 旧：`iot-060a3upv.mqtt.iothub.aliyuncs.com`，明文 `mqtt://:1883`
   - 新：`iot.smartbed.ink`，`mqtts://iot.smartbed.ink:1883`，使用自签 CA 证书建立 TLS 连接

2. **MQTT 签名算法调整（`aiot_mqtt_sign.c`）**
   - 旧：固定时间戳 `2524608000000`，固定 `securemode=2`
   - 新：通过 `gettimeofday()` 获取**实时毫秒时间戳**参与签名；`clientId` 扩展字段与密码签名使用同一时间戳（与涂鸦控制台工具规则一致）
   - 当前配置：`securemode=2`（与控制台 JSON 一致）

3. **连接时序调整**
   - 旧：WiFi 初始化阶段即创建 MQTT 客户端
   - 新：**获 IP → SNTP 时间同步 → 重新签名并创建/启动 MQTT 客户端**
   - 避免 SNTP 未完成时 timestamp 错误，导致连接后被云端主动断开

4. **SNTP 优化**
   - SNTP 初始化从 `app_control.c` 迁移至 `use_wifi.c`，在 `GOT_IP` 后触发
   - NTP 服务器改为 IP 直连（`203.107.6.88` / `114.118.7.163`），减少 DNS 解析延迟
   - `utc_get_task` 仅等待 SNTP 同步完成，不再重复初始化 SNTP

5. **连接参数**
   - MQTT `keepalive` 设为 **300s**（涂鸦文档建议 ≥300s，减轻空闲断连）
   - WiFi 省电策略：启用蓝牙时使用 `WIFI_PS_MIN_MODEM`；未启用蓝牙时使用 `WIFI_PS_NONE`

---

## 二、OTA 优化

1. **升级 URL 缓冲区**：`ota.url` 由 **100 字节扩展至 1024 字节**，支持较长 HTTPS 下载链接

2. **下行 JSON 解析增强**
   - 独立函数 `mqtt_handle_ota_upgrade_payload` 解析 OTA 升级包
   - 兼容 `data` 与 `params` 两种 JSON 字段结构

3. **版本上报策略变更**
   - 旧：仅在 `otaFlag=1` 时上报一次 `/ota/device/inform`，随后清 flag
   - 新：**每次 MQTT 连接成功均上报**当前版本，便于云端匹配升级任务并主动推送 upgrade

4. **下载稳定性**
   - OTA HTTPS 下载前 **暂停 MQTT TLS**，释放内部 RAM 给第二路 mbedTLS
   - 下载失败或中止后 **恢复 MQTT 连接**
   - 增加防重复升级（进行中忽略新的 upgrade 推送）
   - OTA 任务栈由 **4K 增至 8K**

## 三、5S / 60S 数据上报

1. **新增字段 `sensor_ts`**
   - **5s 数据（type:1）**、**60s 数据（type:2）** 的 `data` 对象中增加 `sensor_ts`
   - `ts`：ESP 侧上报时刻（UTC 秒）
   - `sensor_ts`：传感器 protobuf 包内的时间戳，供云端对齐业务采样时间

   示例（5s）：

   ```json
   {
     "id": "KSPSBED00001057",
     "ts": 1710000000,
     "type": 1,
     "data": {
       "sensor_ts": 1709999995,
       "heart": 72,
       "breath": 16,
       "status": [0, 0, 0, 0, 0]
     }
   }
   ```

2. **60s 上报频率修复（重要）**
   - `UP_RATIO_60S` 由 **6 改为 12**
   - 修复 `cnt_5s` 初值设置错误导致 **60s 与 5s 同频误发** 的问题
   - 现逻辑：每 5s 上报一次，累计 12 次后再发 60s（约 60 秒一条）

## 四、Bug 修复与稳定性

| 类别 | 说明 |
|------|------|
| CRC16 字节序 | `set_bc()`、`sensor_ota_bc()` 中 CRC 高低字节顺序修正 |
| 串口解码长度 | `qs_pb_state_raw_data_decode` 改用 `uart_recbuff[3]-1`，不再使用固定 `sizeof` |
| 空指针防护 | `set_bc` 报告列表解析增加 null 检查，避免异常崩溃 |
| MQTT 收包安全 | 增加 topic/data 长度校验、字符串 `\0` 结尾、忽略分片消息 |
| 日志优化 | 关闭 5s protobuf 大量 debug 打印；新增 SU2/MFP 串口调试宏（默认关闭 MFP 流量日志） |

## 五、V2.2.4 已有功能（本版未改动，供对照）

以下为 V2.2.4 相对 V2.2.3 的变更，V2.3.4 继承保留：

- 闹钟指令 `0x04`：APP 下发闹钟后 **120s 内禁止新的打鼾干预触发**（不打断当前进行中的干预）
- 打鼾干预 MFP 发送方式改为 `prepare_mfp_command` + 重试 3 次
- 清理旧版 MFP 串口接收注释代码

## 六、云端 / 对接侧注意事项

1. **MQTT**：需切换至涂鸦域名 `iot.smartbed.ink`，使用 MQTTS（端口 1883 + TLS），ProductKey 仍为 `ixvaCaIfGla`
2. **5s/60s 数据**：JSON 解析需兼容新增字段 `sensor_ts`
3. **OTA**：设备每次上线均会上报 inform 版本；upgrade 下行 JSON 可使用 `data` 或 `params` 包裹 `version`、`url`
4. **60s 频率**：云端若按上报间隔统计，60s 数据恢复为约 1 分钟一条（此前版本可能误为 5 秒一条）
