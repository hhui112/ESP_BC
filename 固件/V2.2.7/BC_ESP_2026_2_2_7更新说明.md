**维护分支：** `v2.2.4-sensor_ts`（阿里云 MQTT 路线，**不合并**至 `project` / V2.3.4 涂鸦路线）  
**基准版本：** V2.2.4（`BC_ESP_2026_2_2_4`，提交 `060739e`）  
**本版版本号：** `BC_ESP_2026_2_2_7`

## 一、版本号体系统一

1. **`INIT_VERSION` 为唯一人工版本源**（`components/common/common.h`）
   - 修改后须执行 `idf.py fullclean build`（或 reconfigure），使 bin 内 `esp_app_desc.version` 与业务号一致。

2. **CMake 自动同步 `PROJECT_VER`**
   - 根目录 `CMakeLists.txt` 从 `common.h` 读取 `INIT_VERSION` 并写入编译产物。
   - 用途：OTA 双槽镜像版本可读、回退时从目标分区 `app_desc.version` 写回 NVS。

3. **版本存储说明**
   - **NVS `version`**：业务上报版本（MQTT `running_version`、inform 等）。
   - **bin `app_desc.version`**：编译时 `PROJECT_VER`（与 `INIT_VERSION` 对齐）。
   - **OTA 成功**：仍以云端下发的 `upgrade_version` 写入 NVS（`upgrade_nvs_infor`），**不**用 app_desc 覆盖。
   - **OTA 回退成功**：将目标槽 `app_desc.version` 写入 NVS，并置 `otaFlag=1`，重启后 inform 上报。

## 二、OTA 分区回退（新功能）

在保留 V2.2.4 阿里云 OTA 流程基础上，增加 **双槽镜像回退**，便于升级异常时切回上一版固件。

### 1. MQTT 下行指令（`deviceCli`）

| 指令 | 说明 |
|------|------|
| `otaRollback` | 切换到**当前非运行槽**（推荐，与 OTA 写入策略一致） |
| `otaRollback0` | 强制下次从 **ota_0** 启动 |
| `otaRollback1` | 强制下次从 **ota_1** 启动 |

**应答 JSON 字段：**

- `running` / `running_ver`：回退前运行分区及镜像版本  
- `target` / `target_ver`：回退目标分区及镜像版本  
- `back`：`ok rebooting` 或失败原因（如 `ota in progress`、`ota_1 empty or invalid`）

回退成功：设置 boot 分区 → 写 NVS 版本与 `otaFlag=1` → 约 800ms 后重启。

### 2. 上电分区日志

启动时在 `device_init()` 之后调用 `ota_log_boot_partition_info()`，串口打印：

- 当前 **running** 分区及镜像版本  
- 下次 **boot** 分区及镜像版本  
- **ota_0 / ota_1** 两槽 `app_desc.version`（空槽会提示 `empty or invalid`）

### 3. 使用前提与限制

- 分区表仍为 **factory + ota_0 + ota_1**（各 2M），**factory 不参与**本版回退逻辑。  
- **须至少完成一次 OTA**，使非运行槽存在合法旧镜像；仅 UART 首次烧录、未 OTA 时，另一槽常为空，**回退会失败**（属预期）。  
- OTA 进行中（`get_ota_now_flag()`）时拒绝回退。  
- 本版**未实现**禁止降级的 OTA 校验；能否回退取决于另一槽是否仍有可用旧 bin。  
- 重复 OTA 升级请求：若已在 OTA 中，忽略新的 `ota_start`（日志：`OTA already in progress`）。

## 三、5s / 60s 数据上报：新增 `sensor_ts`

1. **5s 数据（type:1）**、**60s 数据（type:2）** 的 `data` 中增加 `sensor_ts`：
   - `ts`：ESP 侧 MQTT 上报时刻（UTC 秒）  
   - `sensor_ts`：传感器 protobuf 包内时间戳，供云端对齐业务采样时间  

   5s 示例：

   ```json
   {
     "id": "KSPSBED00001057",
     "ts": 1710000000,
     "type": 1,
     "data": {
       "sensor_ts": 1709999995,
       "heart": 72,
       "breath": 16,
       "status": [0, 0, 0, 0, 0]
     }
   }
   ```

2. **说明：** 本分支自 V2.2.4 演进，**未包含** `project` 分支 V2.3.4 中的 60s 上报频率修复（`UP_RATIO_60S` 6→12 等）。若现场 60s 与 5s 同频，需后续在本分支单独合入或升级至涂鸦 V2.3.4 路线。

## 五、编译与烧录

1. 确认 `INIT_VERSION` 为 `BC_ESP_2026_2_2_7`。  
2. 修改版本或 CMake 后：`idf.py fullclean build`。  
3. 烧录分区与 V2.2.4 一致；本目录可附带 `ota_data_initial.bin`（OTA 数据分区初始镜像，按需使用）。  
4. 验证建议：
   - 串口确认两槽 `app_desc.version` 与 NVS `version`；  
   - OTA 升级后再测 `otaRollback`；  
   - 确认 5s/60s JSON 含 `sensor_ts`。
